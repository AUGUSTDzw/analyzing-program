# 检查器缺陷导致 A8 指标虚高 —— 已修正，结论也随之改变

## 我错在哪

`qc_report.py` 把**每一个** ` ```abap ` 围栏都当成"引用源码的代码块"，
因而要求它后面必须有三层标签。

但报告里有一类 ` ```abap ` 片段是**嵌在 `风险与改进` 层里、用来展示改法的示意代码**，
例如：

```
**风险与改进** — 这里有四个问题，其中前两个是必然出错的：

1. **`ID_TITLE` 在这里本该被用上，却被完全忽略**（P0-1）。正确写法是：
   ```abap
     IF id_title IS INITIAL.
       id_title = 'Show Error Log'(001).
     ENDIF.
   ```
   这样既保住现有默认行为，又让参数真正生效。
```

这段不是源码引用，skill 的「Code Block Rules」管的是源码引用，不管示意片段。
我把它算成了违反，于是**A8 指标系统性虚高**，而且虚高的恰好集中在问题最少的报告上
—— 因为报告写得越细，"风险层里贴改法"的次数就越多。

**修正后这两个文件的违反数是 0 和 0，不是 3 和 1。**

## 结论

1. **A8 不是这个 skill 的普遍问题。** 8/9 报告零违反。它是**超长文件专属**问题
   （29.5k 行 → 74%），而 29.5k 行的报告目前生成不稳定，所以**恰好无法验证修复**。
2. 我此前基于"28% 违反率"做的判断（"这是最高频的失分形态"、"要改模板"）
   **前提被夸大**了 4 倍。真正需要修的是"超长文件如何保持三层标签"，
   而这在当前 harness 下测不了。
3. 三次测量缺陷同型：**用一个看起来对的正则/计数去断言"某构造不存在"或"某指标多高"，
   实际是探针错了**。此前有 AMDP 探针（匹配方法体而非声明）、
   `CLASS x IMPLEMENTATION.` 探针（漏行尾句点）、`RANGES` 被列为过时语句、
   以及把 `mm` 列读成 `ln` 列。这一次是同一类。

## 下一步（若继续）

- **不要**再为 A8 改 skill。先把 29.5k 行文件的**生成可靠性**解决（目前截断），
  否则唯一暴露问题的场景永远测不了。
- 或者反过来：**接受**"超长文件 A8 会退化"这个事实，在 skill 里加一句针对大文件的
  产出建议（按功能簇分组、每簇一个代码块），而不是追求块级三层。
- FI toolkit 两次生成失败是子代理侧问题（空返回 / 截断），不是 skill 问题，
  但同样让"激活问句"无法验证。
