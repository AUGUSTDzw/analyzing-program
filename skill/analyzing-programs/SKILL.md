# Skill: analyzing-programs

# Analyzing Programs（ABAP/SAP 程序分析报告）

## Overview

You are a senior engineer giving a colleague a code onboarding walkthrough. Given an ABAP/SAP program source file, produce a professional, deep, execution-flow-oriented analysis report. After reading it, the reader should: understand the business problem solved, grasp the architecture, and form their own thinking.

Default output language: Chinese. Follow the user's language if they ask in another language.

The value of this skill is the **fixed report structure** and the **three-layer per-code-block format** — they make onboarding reports consistent and skimmable. Always load and follow the full rules below before writing; do not produce the report from this description alone.

## Analysis Flow

1. **通读源码**：扫描入口、目录结构、依赖、声明段，识别程序类型（报表/服务/库/工具）与核心特征。
   **源码是粘贴进来的、而不是一个已存在的文件时，先把它原样写成一份 UTF-8 编码的
   文件再往下走**（例如 `pasted.abap`），第 6、7 步的闸门要的是**路径**，不是内存里的文本。
   **编码是硬要求：源码和报告都必须是 UTF-8，否则闸门以退出码 `2` 拒绝运行**，
   一个字都不比对。从 SE38 复制出来另存的文件容易是 cp936，这是最容易踩的一条
   ——先转成 UTF-8 再跑；报告同理，编辑器"另存为"默认会落到 cp936。
    还有第三种：**文件是合法 UTF-8，但保存时把一个多字节字符截断了**，解成 U+FFFD
    替换字符。闸门以 `enc` 缺陷报出，退出码是 `1` 不是 `2` —— `2` 是读不出来，
    `enc` 是读得出来但已经坏了。改法是回原文件重新另存为 UTF-8；**不要手动删掉
    替换字符**，删掉它等于把丢失的内容当成没丢。
    **扩展名没有要求**：闸门按扩展名区分报告与源码，`.md` / `.markdown` 一律当报告，
   其余一律当源码，`.txt`、`.ab1` 都算源码（见第 7 步）。
2. **识别子程序边界**：找出所有方法/函数/事件块/声明区，作为分组单位。
3. **确定执行流程**：按程序真实运行顺序（从入口到结束）排列这些子程序。
4. **逐子程序分析**：每个子程序给出"做什么 / 为什么 / 风险与改进"三层。
5. **汇总问题与评价**：把跨子程序的问题按优先级汇总，给出整体评价。

   **收笔前先答两道题，否则会带着没答的问题发货。** 这两条 note 问到的东西
   第 6、7 步都补不上 —— 那两步不许动分析，`--fix` 也只修 `ln` 与 `mm` ——
   所以必须在这里就写进去：
   - 源码读了数据（`SELECT` / `READ TABLE` / 取数函数）却全文没有 `AUTHORITY-CHECK`
     → §5 或对应层的「风险与改进」写一句后果：**谁能因此看到什么**。
   - 源码把位图/图标名写成字符串字面量（`Z…_LOGO`、`…_ICON`、`…_BITMAP`）
     → 写一句每个调用点到底在不在 `TRY` / `EXCEPTIONS` 里；
     只说"这是硬编码的外部依赖"不算回答。

6. **全部写完之后，另起一轮，只修引文**：运行
   `python scripts/report_qc.py --fidelity-only 报告.md 源码.abap`。
   **当前目录必须是本 skill 的根目录** —— 命令里是相对路径，闸门**不会**自己定位规则集
   （`abap_deps_analyzer.py` 会，`report_qc.py` 不会）。目录不对是 `can't open file`，
   那不算跑过闸门。也没有 `--help`：它按扩展名挑报告路径，`--help` 会被当成「没给报告」
   而以 `2` 退。
   它只回答一件事：**你引用的语句是否逐字存在于源码里**。有就对照源码改正，然后重跑，
   直到**退出码为 0**为止。判据见「闸门输出」，不要靠输出文字判断。
    （报告或源码路径不存在、源码不是 UTF-8、或规则集读不到时，闸门以退出码 `2`
    **拒绝运行**，输出以 `error` 起首——见「闸门输出」。这一模式下源码**必须恰好一个**，
    少给或多给同样退出 `2`。）

   **这一轮不许改分析。** 只能改引用源码的 ABAP 片段；不许增删或重写任何论述、
   不许调整章节结构、不许"顺手改进"风险或结论。**分析在这一步已经是终稿。**

   为什么要分成两轮：把闸门放进生成过程，实测**方向上**会吃掉一部分缺陷召回——
   20 条与 38 条两个分辨率同号。但**幅度不作数**：那批实验的单元数太少，
   点估计被噪声淹没，所以这里只保留方向，不写百分点，也不据此排序改动。
   同一批实验里，只查引文和查全部的两臂记分完全相同（p=1.0），所以损失来自回路
   占用写作预算，与查什么无关 —— 规则不是「少查」，是「换个时刻查」。
   引文准确性也不归这条规则：实测每一轮都能自查出转写错误（两处到八处不等，
   取决于跑的是生成内检查还是写完之后那一轮），但那是忠实度诊断的功劳。

   形状（六节、三层、四个优先级桶、Mermaid、位置标签）由第 7 步检查。

7. **再另起一轮，跑形状闸门**：带上源码运行
   `python scripts/report_qc.py 报告.md 源码.abap`（同样，当前目录是 skill 根目录）。
    它查：**围栏闭合**（`fence`）、六节结构、第五节至少一条问题行、三层标签、
    四个优先级桶、Mermaid 标签可渲染、位置标签不带行号。
    其中 `fence` 排序最靠前——围栏没闭合时报告后半段全部落在围栏里，其余检查全都
    无从谈起，所以先修它。
   判读只看退出码，见下一节；拿到退出码 `0` 之后还要确认命令行里确实带了 `.abap` 源码，
   否则「通过」只代表形状对。完整检查表见 `schemas/report-contract.json`。
   **这一轮同样不许改分析。**

   闸门只管形状。**分析对不对、漏没漏，它答不了** —— 那需要一份冻结的缺陷清单，
   见 `evals/README.md` 与 `scripts/evaluate.py`。

## 闸门输出：退出码是唯一的机器判据

`scripts/report_qc.py` 的**退出码**是唯一的机器判据，输出行只是给人看的：

| 退出码 | 什么时候 | 意味着什么 |
|---|---|---|
| `0` | 检查跑完了，**形状无缺陷，且没有实质改写**（三种模式一致） | `PASS  <报告名>`。可能带 note，**note 不改变退出码** |
| `1` | 跑完了，有缺陷 | 形状模式：缺陷行以 `fence` / `sec` / `sec-dup` / `prow` / `row-src` / `buck` / `ln` / `mm` / `mm-missing` / `A8-cc` / `layer-same` / `A8-pt` / `enc` 起首，**加上忠实度实质级的一行 `SUBSTA`**，然后是 `FAIL  <报告名>  (N defect(s))`，`N` 把两者都算进去。`--fidelity-only`：先打 `SUBSTA` / `PUNCT-` 分级行，末行 `FAIL  <报告名>  (N rewrite(s), M punctuation-only)`；没有实质改写则 `PASS`。`--fix`：`FAIL  <报告名>  (N shape defect(s) and M rewrite(s) need the model)`，两类各数各的，只剩一类时只打那一类；**实质改写同样让 `--fix` 退 `1`**，三种模式给同一个答案 |
| `2` | **拒绝运行：一个字都没查** | 绝大多数情况输出以 `error` 起首。两个例外不带 `error`：不带参数时打印用法说明；`--fix` 路径不足时打印 `--fix needs REPORT and SOURCE` |

`2` 的全部触发条件，按模式分：

| 模式 | 触发条件 |
|---|---|
| 通用 | 没给参数；命令行里没有 `.md` / `.markdown` 结尾的报告路径；报告路径不存在；**规则集 `schemas/report-contract.json` 读不到或已损坏**；**`scripts/checks/` 缺失或其中某个模块解析不了**；**报告或源码任一不是 UTF-8**；**闸门自己在检测器里抛异常** |
| 形状（第 7 步） | 源码路径不存在；给了多于一个源码 |
| `--fidelity-only`（第 6 步） | 没有报告路径；源码不是**恰好一个**（0 个与 2 个都拒）；源码路径不存在；**源码是空的** |
| `--fix` | 少于两个路径；没有报告路径；源码不是**恰好一个**；`-o` 后面没跟输出路径；**`-o` 所在目录不存在或不可写**；**`-o` 指向源码本身** |

五条容易读错：

- **两个文件里有任何一个不是 UTF-8，三种模式都拒绝。** 读不出来就没有可比对的东西，
  比对没有意义。**这一条对报告同样成立**——报告是编辑器"另存为"的产物，
  在中文 Windows 上默认就是 cp936，和从 SE38 另存的源码是同一个坑。
- **源码是空的只在 `--fidelity-only` 下拒绝。** 形状模式还能查形状，所以它打**两条**
  `note` —— 一条说没有可计的分母（密度没测出来），一条说文件是空的 —— 然后照常返回
  形状结论；`--fidelity-only` 拿空源码做不了任何事，所以拒绝。**报告为空不在这条之列**
  —— 空文件照样按形状检查。
- **闸门崩溃也是 `2`，不是 `1`。** 检测器抛异常会打印
  `error  internal error checking <报告>: <类型>: <消息> -- the gate crashed, so treat this report as unchecked, not as defects found`
  并退出 `2`。`1` 的意思是「查过了，有缺陷」——崩溃若也算 `1`，第 6、7 步会让你反复去修
  一份并不存在的缺陷，永远到不了 `0`。看到这条 `error` 是**闸门的问题，不是报告的问题**：
  不要去改分析，换一份源码或上报闸门缺陷。
- **形状模式也查忠实度，`SUBSTA` 计入 `N`。** 所以「形状对」不等于 `0` —— 只要有一句
  引用里的标识符、字面量或数字与源码不同，第 7 步仍然退 `1`。这正是第 6 步存在的理由：
  先把引文修干净，第 7 步才只余形状。
- **verdict 不是最后一行。** 形状模式与 `--fix` 都在 `FAIL` / `PASS` **之后**再打 note，
  最多七条。按「末行」定位 verdict 就停，会漏掉全部 note —— 包括那条告诉你五项诊断没跑
   的。忠实度的分级名在输出里被截成六个字符：`SUBSTANTIVE` 打成 `SUBSTA`，
   `PUNCT-ONLY` 打成 `PUNCT-`，照全称 grep 什么都找不到。**`--fix` 一行分级行都不打**，
   只用一条 note 说有几处改写，所以在 `--fix` 的输出里 grep `SUBSTA` 也是空的。

🔴 **CHECKPOINT · 退出码 `2` 是「拒绝」，不是「通过」。**
它意味着闸门一个字都没看。把路径改对再重跑；**不要**因为没看到 FAIL 就当没问题。

🔴 **CHECKPOINT · 源码是可选参数，所以「形状对」不等于「查过了」。**
不带源码跑形状检查仍会打印 `PASS` 并返回 `0`，但会多出一条 note：
`no source recognised, so density, fidelity, fix-mislabel, authz and ext-asset were not run`。
**看到这条 note 就等于那五项诊断没跑**（六条里只有 fix-lang 不需要源码），必须带上源码重跑。第 7 步因此必须带源码，
而退出码 `0` 只能读作「形状对」。

两个容易踩的写法：

- **报告路径必须以 `.md` 或 `.markdown` 结尾，命令行上其余路径一律当源码。**
  反过来把源码存成 `.txt` / `.ab1` 是安全的；把**报告**存成 `.txt` 则会让闸门认为
  你没给报告，直接 `error` 退出 `2`。
- **一次只能给一个源码。** 给两个会 `error` 退出 2，而不是静默取最后一个 ——
  后者看起来像一次成功运行，其实只拿一份报告对了个空。

### 六项诊断：note 不改退出码，但要看

闸门跑完还会打印最多**七**条 `note`：下面六项诊断各一条，而忠实度按严重度分两级
（实质改写与仅标点差异各打一条），所以是七条上限。它们**不改变退出码**，所以闸门不替你
判读 —— 得你自己看。唯一例外是忠实度的实质级：它**同时**打印一行 `SUBSTA` 缺陷并计入
`FAIL` 的 `N`，那是一条真缺陷，不只是 note。

| 诊断 | 它在问什么 | 需要源码 |
|---|---|---|
| 密度 | 形状完整却只是一份名录。**分组单位的展开深度**（引用的代码块数 ÷ 源码里声明的子程序数）低于契约给的 `floor_blocks_per_subprogram`（目前 `0.5`）时打一条 note。**它不改退出码**——低于下限的报告照样返回 `0`，补不补展开由你判断 | 是 |
| 忠实度 | 你引用的语句是否逐字存在于源码。**实质改写还会打印一行 `SUBSTA` 并计入退出码**；仅标点差异只打 note | 是 |
| fix-lang | 示意改法有没有被留在 ```abap 围栏里 | 否 |
| fix-mislabel | 反向：```abap-fix 围栏里的语句如果**整块逐字连续出现在源码里**，它就不是改法，而是**贴错了围栏的真引用** | 是 |
| 授权 | 源码取了数据（`SELECT` / `READ`）却**全文没有 `AUTHORITY-CHECK`**。报表跑在 `S_TCODE` 授权下，所以这**本身不一定是缺陷**——note 只问一句，不是结论。报告若给出后果（谁能因此看到什么），这条 note 就消失 | 是 |
| 外部资产 | 源码把位图/图标名写成字符串字面量（`Z..._N_..._LOGO` 这类）。这类对象在目标系统里，**编译器和语法检查都看不见**；缺图时报错出现在运行期。note 报出名字与源码里 `TRY`/`EXCEPTIONS` 的总数，请你确认每个调用点是否真在某个保护里 | 是 |

后两条只覆盖**可确定性判定**的那部分：`AUTHORITY-CHECK` 零次出现是事实，外部资源名是字面量也是事实。
**它们不替你判断"这是不是缺陷"**——`S_TCODE` 之外的口径差别、`TRY` 有没有包住正确的调用点，
都得你读源码自己答。note 的作用是把这个问题**摆到你面前**，不是替你下结论。

⚠️ **两条 note 的消音规则不一样，别当成同一条。**「授权」有门槛：报告里写出
一句后果（谁能因此看到什么）它就消失。**判"写了后果"靠的是正则字面匹配，不是判断
你对不对** —— 命中下面任意一个即消音：`越权`、`未受控`、`无权限隔离`、`看到全量`、
`任何能运行` / `任何可运行`、`任意用户`、`全体用户`、`数据权限`、`SoD`、`职责分离`。
**这是字符串，不是近义词**：「任何人」不命中（正则要的是 `任何` 紧跟 `能运行` 或 `可运行`），
「其他用户」不命中，「全部用户」也不命中 —— 得写 `任意用户` 或 `全体用户`。
只写"不做权限控制"不构成回答，那只是把观察又说了一遍，正是这样被判为 partial
的报告。
「外部资产」**没有门槛**：源码里只要有一个位图/图标名字面量它就会发，你写多少句
都不会让它消失。它要的是你在正文里答一句"每个调用点到底在不在保护里"，
不是让你让 note 闭嘴。

fix-mislabel 之所以存在：`abap` 与 `abap-fix` 只锁了**一个方向**。留在 ```abap 里的
改法会被回对源码、因此被抓住；而**贴进 ```abap-fix 的源码永远不会被回对源码** ——
语言标记因此能给一段引用开后门，而那个检查存在的目的正是抓编造的引用。
单方向的围栏就是这类漏洞出现的形状，所以围栏语言必须双向都锁死。

这条的判据是**连续**，不是"每条都出现过"。改法里引用了待改的那一行、各行都能在源码
某处找到，是合法写法——实测它曾因此在九份真实报告上误报五次。所以它只在**整块逐字
连续**对得上源码时才提出来。

**忠实度比对的是代码，不是注释。** 一句 `DATA lv_msg TYPE string. " 物料` 参与比对的是
`"` 之前的部分。注释是文字，改写注释不构成改写语句；反过来，把一条语句写错却留着原注释
照样会被抓住。围栏里的整行中文（报告自己的点评）不参与比对——中文出现在字符串字面量和
语句注释里时**仍然算代码、仍然要比对**，这是最容易想反的地方：`WRITE / '开始'.` 是一条
真语句，不是点评。

**密度的分母只数构造，不数声明段。** 分母是源码里出现的类 / 接口 / 方法 / 表单 /
函数 / MODULE / 定义 / 过程；CLASS-DATA、CLASS-METHODS 这类声明段不计入。所以把声明段
单独写成章节不会拉低密度，但只写声明段、不展开方法会。

**密度、忠实度、fix-mislabel、授权、外部资产这五项都需要源码。** 不带源码跑形状检查时它们都跑不了。
另外一条 note（fix-lang）不需要源码。

### 自动修：只有两类判断改不动，所以只有两类能自动修

`--fix` **只修**两件不会改变意思的事（它仍然会跑完全部检查并照常报告，包括忠实度）：

- **位置标签里的行号** → 换成最近的前置构造名。找不到可靠锚点时**原样留下**并记一条
  note，不硬猜。
- **Mermaid 标签里的裸 `<` `>` `#`** → 换成全角。成对的 HTML 子集标签不动。

它**不修三层缺失** —— 那要判断后面的散文本属于哪一层，猜错会把风险论述标成"做什么"。
原地重写**并且确实改了东西**时，它会把原文另存为 `<报告名>.bak`，并保留报告自己的换行风格。
零修复时不写 `.bak` —— 但它仍会把重写后的文本原地写回，所以正是「什么都没修」的那次没有备份。
修完仍有缺陷时返回 `1`，不会假装修好了 —— **一句改写的引文也算**：它不是 `--fix` 能修的，所以也算「还有缺陷」，照样退 `1`，与形状模式同一个答案。

所以用法是：**先按规则写对，再用 `--fix` 收机械残留**。它改不动的那些，
正是要人判断的。

## 大输入：先读 `references/large-inputs.md`

子程序多到写不完时，**不要靠猜**。那份文件记的是实测：一次任务写不完是常态，
失败有三种形态——**静默**（什么都没产出）、**截断**（停在第三节中间，句子断在半途）、
**写完但变薄**。

两条必须一起记的量，都带协议标签：

- 14 次派发完整率 4/14（29%），其中 6 次静默、4 次截断 —— 测的是
  **FI toolkit**（约 1700 行、18 个子程序）、**更早的 harness 与更早的 skill 版本**。
- 在 `objects_program`（1597 行）与当前版本上，**不要求额外交付物**的条件下
  9 次派发全部产出。

**两个数不能并列、也不能互相替代**：文件不同、协议不同。第二个数只说明
"这一类输入在这个版本下目前写得完"，不构成任何完成率断言。

🔴 **CHECKPOINT · 没写完就不要报「完成」。**
把覆盖范围写进第六节，例如"共 N 个子程序，完整展开 M 个，其余仅列名"。
说清哪些没读，比假装都读过有用得多。截断的报告比缺失的报告更危险：
它还是文件、会被计数、看起来像数据。

## Three-Layer Format per Code Block（核心规范）

每个子程序 section 内，**每个代码块**之后必须给出三层，三层缺一不可。

三层标签必须**显式出现**（`#### 做什么` 或 `**做什么**` 二者任一即可）。**不得用无标签的散文点评代替三层**——散文会让读者无法快速定位"这段的风险在哪"，正是本格式要解决的问题。

**三层必须紧跟本块的围栏，窗口有明确边界。** 闸门取的是：从本块**闭合围栏**到
**下一个任意语言的围栏**或下一个标题之间的文字 —— 不是到下一个 ```abap 块。
中间夹一个 ```abap-fix 块时，那块里的三层标签不算本块的三层。
窗口内文字去空白后不超过 20 字时按 `A8-cc` 报（压根没有评述），
超过则按 `A8-pt` 报（有评述、缺标签）。

### 第一层：做什么
- 用连贯自然语言描述，核心句式："从哪张表/数据源，用什么条件，取/做什么数据，得到什么结果，存到哪里/回填到哪"。
- 不要逐句拆碎成"第 X 行：…"的流水账。
- 用 markdown 列表分段，一项一个动作（取数 / 遍历 / 回填 / 排序 / 装配…），每项一句，不要挤成一长段。

#### 写完对照一遍：笼统 vs 具体

上面那句式是**检查清单**，不是可以跳过的手续。写完第一层，逐项自问四件事：

**数据源**（哪张表/哪个类/哪个 FM）· **筛选条件**（什么 WHERE、什么区间、什么 sy- 字段）
· **取什么数据**（哪几个字段、什么结构）· **结果去哪**（装进哪张内表、回填哪一列、输出到哪里）

四问里有两问答不上来，就是写笼统了。对照：

```
❌ 处理物料数据，填充内表。
✅ 从 MARA 按 matnr IN s_matnr 取 MATNR 一列装进 it_mara，筛选条件是选择屏区间。
```

```
❌ 调用消息类显示提示。
✅ 通过全局类 ZCL_BC_SCREEN_MESSAGE 的静态方法 OUTPUT，把字符串 'Show Error Log'
   后面拼接上消息类中的文本 001，作为一条屏幕提示输出。
```

```
❌ 遍历错误日志，更新行数。
✅ 遍历错误日志内表，从第 7 行起每读到一行就把函数组全局变量 GD_END_LINE 加 1，
   加到 35 就不再加。净效果：错误超过 6 条时列表框每多一条就长高一行。
```

**每层至少点名一个源码里的具体对象**——表名、类名、方法名、变量名，用反引号标出来。
`做什么` / `为什么` 两层尤其要用：**点名对象的层，读者才能回源码核对；不点名的层只能靠信任。**
范例报告里 5 条 `做什么` 全部点名了源码对象，可以直接当标尺比。

⚠️ 闸门查不出笼统。它只查标签在不在、窗口正文有没有超过 20 字；
`evals/` 里的缺陷问的也是"报告有没有指出源码里的某个缺陷"，不是"写得细不细"。
所以这一层只有你自己把关。

### 第二层：为什么 / 设计点评
- 讲动机、权衡、替代方案代价。不只是"用了什么"，而是"为什么适合这场景"。
- 与业界最佳实践对比，指出领先处与改进空间。

### 第三层：风险与改进
- **每个代码块后三层都必须出现**，不得对有风险的步骤静默省略第三层。
- 指出真实问题，不回避缺陷；给出具体改进方向。
- 仅当某步骤为纯样板/确无风险时，可写"无明显风险"一句带过，但仍需保留该层标题，不得直接跳过。
- **本层给的是"待审草稿"，不是可直接采纳的方案。** 每条改法都要能被读者复核。

#### 写到具体标识符就必须往下推一步 —— 停在名词上不算第三层

这一层最常见的失分**不是漏看，是看到了却没推到底**：点名了那个字段/方法/FM，
然后用一句描述性的话收尾，转去写下一条。读者拿不到任何可行动的信息。

**规则：每写出一个具体对象（表名、类名、方法名、字段名、FM 名），紧跟一句它的
运行期后果——它为初始、被并发改写、超时、越界、目标系统不存在时会发生什么。
只有名词没有后果，不算写完。**

```
❌ 位图名 ZCHEM_N_LOGO_SMALL 是硬编码的外部依赖，属于跨行业遗留。
✅ 位图名 ZCHEM_N_LOGO_SMALL 是硬编码的外部依赖，且调用它的 display 外面没有
   包 TRY：目标系统缺该图形时异常在显示阶段抛出，用户看到的是一张空屏幕加一条
   短转储，看不出是图形没上传。
```

```
❌ s_lifnr 是内表类型，未定义键。
✅ s_lifnr 声明成标准表而非 HASHED，回填名称段时每行都要线性 READ TABLE，
   万行规模下是 O(n²)；改成 SORTED 或 HASHED 由 SORT/READ 维护索引即可。
```

自检：把第三层里每个反引号里的标识符列一遍，**逐个问"它出事会怎样"**。
一个都答不上来的条目，删掉它或补上后果。

### 拆分步骤时（① ② ③）怎么办 —— A8 失分高发区

大代码块被拆成多个小代码块后，**每个步骤同样必须带齐自己的三层**。拆了不等于可以省标签。

**推荐紧凑写法**：标签行内加粗，不再各套一层 `####`，避免标题层级膨胀、也避免"步骤标题挤掉了三层标题"。
**"紧凑"指标题层级，不指空行**——三层之间照旧要各空一行，见下节的分段规则。
**注意第二步演示了「一步两块」**：当一个步骤天然含多段代码时，可以分成多个代码块，
但**每块后面都要跟自己的三层**，不能把三层合并到整步最后一块之后：

````markdown
#### ① 取物料号

```abap
SELECT matnr FROM mara INTO TABLE it_mara WHERE matnr IN s_matnr.
```

**做什么** — 只取 MATNR 一列装进 `it_mara`，筛选条件是选择屏区间。

**为什么** — MARA 有 200+ 字段，投影取列省内存；MATNR 上有索引，区间扫描代价可控。

**风险与改进** — `s_matnr` 非必填，等于允许全表扫描；建议在取数开头拦截空选择屏。

#### ② 声明与取描述（两步代码，块级三层）

```abap
DATA: lt_mara TYPE TABLE OF mara-matnr,
      lt_makt TYPE TABLE OF makt-maktx.
```

**做什么** — 声明两张窄内表，`lt_mara` 存物料号、`lt_makt` 存描述。

**为什么** — 只装用得到的列，避免把宽结构整体搬进内存。

**风险与改进** — 未指定表键，两张表都是标准表，后续 `READ TABLE` 会退化为线性查找。

```abap
SELECT matnr maktx FROM makt INTO TABLE lt_makt
  FOR ALL ENTRIES IN lt_mara WHERE matnr = lt_mara-matnr AND spras = 'EN'.
```

**做什么** — 取 MATNR + MAKTX，用 FOR ALL ENTRIES 与 lt_mara 做内连接。

**为什么** — 命中 MAKT 的 MATNR+SPRAS 索引前缀，比裸 JOIN 更可控。

**风险与改进** — 两处：`lt_mara` 未判空会让 `FOR ALL ENTRIES` 失效；语言硬编码 `spras = 'EN'`，非英文环境不可用，应改 `sy-langu`。
````

**反模式（判定为不合规）**：

1. **把三层揉进一段无标签散文**——读者无法快速定位风险。散文可以写在标签**之内**，不能替代标签。
2. **把一个步骤拆成多个代码块，却只在最后一块后写一次三层**——前面几块就成了没有风险说明的裸代码。
   要么按上面的方式给每块各配三层，要么合成一个代码块。
   最常见的表现是把一个声明段切成两块（`PRIVATE SECTION.` 一块、类型定义另一块），
   但**同一个声明段本来就是一个代码块**。

## Code Block Rules（重点）

- **完整展开，不用 `...` 省略号压缩逻辑代码**。每条语句独立成行。
- **贴出的代码必须逐字符忠实于源码**。不得为让示例"更干净"而改标点、合并或拆分语句，
  不得补上源码里没有的语句。确需节选时用 `...` 并注明省略了什么；
  无法确定某行原文时标注 `<原码此处省略>`，**不要凭印象补写**。
- **重复但有差异的逻辑各自完整展示**。
- **样板清单可用 `...` 省略**：把函数形参逐个提升成全局变量的声明（如把 `REUSE_ALV_*` 全参数提成变量）、接口参数全集、连续同构的字段目录条目——这类代码的价值在"声明模式"而非"每一行"，可用 `...` 省略，并在括号内注明省略了什么（或紧跟表格逐项说明）。**但若某一行正是本节要指出的问题所在（某参数的类型或初值导致风险、某行语法错误），必须展开那一行。**
- 代码块用 ``` 围栏，标注语言。**引源码用 ```abap；源码里不存在的示意改法用 abap-fix 围栏**。围栏语言是"这段是不是源码"的唯一判据——闸门按语言决定要不要逐句回对源码，位置（哪怕落在"风险与改进"标签之后）不做豁免，因为示意改法和下一步骤的真实引用处在同一位置、无法区分。
- **围栏必须闭合。** 少一个结束的 ``` 会让后面全部内容被吞进代码块，于是六节、三层、优先级桶、引文回对**全部失效**而报告看起来仍然完整。闸门以 `fence` 缺陷报出它，并且它是排序最靠前的那一类——修了它，其余检查才有意义。
- **围栏语言要双向锁死。** 留在 ```abap 里的改法会被回对源码；贴进 ```abap-fix 的源码不会被回对源码，所以这个标记既是"这是改法"的声明，也是"别查我"的开关。只把它当声明用，判读办法见「六项诊断」的 fix-mislabel。
- **三层各自起一个新段落——`做什么` / `为什么` / `风险与改进` 之间各空一行。**
  markdown 里连续的非空行属于**同一个段落**，三层挤在一起写，渲染出来是一整段，
  读者没法按层跳读。写法是标签独占一行、**空一行、再写下一个标签**：

  ```markdown
  **做什么** — 只取 MATNR 一列装进 `it_mara`，筛选条件是选择屏区间。

  **为什么** — MARA 有 200+ 字段，投影取列省内存。

  **风险与改进** — `s_matnr` 非必填，等于允许全表扫描。
  ```

  写成三行连排是**反模式**。⚠️ 闸门不报这种错：它只数字符数，三层合并成一段后字符数不变。
  对照 `references/example-report.md` 的写法（那里三层之间是有空行的）。
- **大代码块按逻辑步骤拆分成多个小代码块**，每个小块后仍须带齐自己的三层标签（推荐用上节「拆分步骤时（① ② ③）怎么办」的紧凑加粗写法）。拆分要点：
  - 子程序 section 开头一句话点明分几步。
  - 每个步骤用 `#### ① 名称` 编号子标题。
  - 每个小代码块只含该步骤对应的语句；**同一步骤含多段代码时，按上节示例给每块各配三层**。
  - 衔接语句（FORM 头、ENDFORM 尾）随各自片段自然分布。
  - 紧凑的小子程序保持单块不拆。

## 事实性纪律：不确定就标注，不要编造

**这一层是分析，不是断言。** 读者无法分辨一份报告里的结论是有依据还是猜的，
所以宁可写"需核实"，也不要给出一个听起来合理但错误的答案。

- **拿不准运行时行为、FM/方法参数语义、系统字段在某个位置的值时，写"需在 SE38 / SE11 / SRU 核实"，
  不要写成具体断言。**
- ⚠️ **「需核实」不能当结论句。** 它是**结论之后**的补充，不是结论本身——
  写完它却没有结论，等于什么都没说，读者无法行动。

  **顺序永远是：先给基于源码可判的推理，再补「需核实」。**

  ```
  ❌ EKKO-STATU 的固定值集合及其业务含义需在 SE11 检查该数据元素。
  ✅ 报价段是五段里唯一用 statu = 'A' 当"已维护报价"判据的，而 STATU 记的是
     整张凭证的处理状态，不是报价存在与否；RFQ 那段用的是 b~loekz EQ space，
     两段口径不同。STATU 的合法值集合需在 SE11 核实，但"这里两段口径不一致"
     从源码就能判。
  ```

  ```
  ❌ s_bedat 被声明为选择屏参照字段，但其值需在 SE11 核实。
  ✅ t_disp-bedat 被声明并当作参照字段，但五条查询的 SELECT 列表里都没有
     BEDAT，这一列恒为初始值，随后又被 set_visible(abap_false) 隐藏——
     用户填了日期区间却看不到回显。这一条从源码就能判，不需要核实。
  ```

  **判据：能不能只靠源码读出来？** 能，就直接下结论，不要"需核实"。
  不能（依赖 FM 默认值、依赖系统字段、依赖 DDIC 定义），才补"需核实"，
  而且要写清**不确定的是哪一个值**，不要笼统一句了事。
- 判断不确定的三个信号，命中任一条就标注、不要写死：
  1. 结论依赖某个 FM 的**参数默认值**或**异常是否导出**
  2. 结论依赖某个**系统字段在该位置的值**
  3. 结论依赖**两个 DDIC 字段的长度/类型是否一致**
- **不得反向背书缺陷。** 若某写法确有风险（缺 `sy-subrc`、缺判空、缺锁释放、缺 `COMMIT`、
  未判 `sy-subrc` 就 `MODIFY`），不得因为"当前场景碰巧不出错"而写成"无问题"。
  可以写"当前数据量下不会暴露，但规模变化后即失效"。
- **不得展示源码中不存在的语句。** 需要示意正确写法时，明确标注"建议改为（示意）"，并放在 ```abap-fix 围栏里而不是 ```abap 里。

## Location Labels

- 用所在子程序/方法/事件块名称标注，不用行号。
  - ✅ `（方法 fill_disp）` / `（事件块 START-OF-SELECTION）` / `（全局声明区）`
  - ❌ `（zvend.abap:104）` / `（第 90-96 行）`
- 非方法代码标为"全局声明区"或"类 X 定义段"。

## Grouping Rules

- 以子程序（方法/函数/事件块/声明区）为分组单位，不按文件目录或声明顺序。
- 按程序执行流程顺序排列，不按源码出现顺序。
- 责任链表含"调用者"列，标明每个子程序由谁触发。
- 组与组之间用过渡句衔接，不要生硬转折。

## Writing Style & Depth

- **业务视角优先**：从"解决什么问题"出发，不从"这个文件里有什么函数"出发。
- **Why > What**：描述"是什么"只是起点，解释"为什么这样设计"才是价值。
- **批判性思考**：与业界实践对比，指出真实问题，不回避缺陷，不堆砌优点。**类型与数据元素要做语义校核**：不能只看长度/精度匹配就放过——数据元素名常暗示业务语义（如毛重 brgew 与净重 ntgew、金额 wrbtr 与数量 menge），语义错配即便能跑也应记为风险，不得反向背书为"一致"。
- **有温度**：像资深工程师在白板前讲解，有观点、有推理、有对比，避免 AI 味套话。
- **重点深入次要简略**：核心创新点深入分析，通用工具函数一句带过。
- **行文流畅**：让入门工程师也能看懂并学到东西，避免过度学术化。

## Diagram Rules

- 流程总览用 Mermaid `flowchart TD`，节点命名用子程序名。
- 数据流转用 Mermaid `sequenceDiagram`。
- 责任链/字段配置等用 markdown 表格。
- **Mermaid 标签安全**：节点与 participant 的显示文本不得出现裸 `<` `>` `#` 等 Mermaid 保留字符
  （会被解析为 HTML 或箭头导致不渲染）；尖括号内容改全角或去除，确保可渲染。
  **ABAP 里最常见的碰撞是方法引用的 `->` 与 `=>`**：`cl_demo_output=>display_json( )` 里的
  `>` 就是裸字符。两种写法：**换成全角 `＞`**（`--fix` 做的就是这件事，
  `<`→`＜`、`>`→`＞`、`#`→`＃`），或者**把引用写成文字**（「`cl_demo_output` 的 `display_json`」）。
  **Mermaid 标签的措辞是机械残留，不是分析**：第 6、7 步的「不许改分析」管的是论述，
  不禁止修标签 —— `mm` 缺陷要的就是改标签。
  **例外**：`<br>` `<b>` `<i>` `<u>` `<em>` `<strong>` `<sub>` `<sup>` `<code>` `<span>`
  这类成对标签内的尖括号不算裸字符 —— 它们是 Mermaid 支持的 HTML 子集，闸门不报、
  也不该被改成全角。把原本能渲染的图改坏，比留着尖括号更糟。
