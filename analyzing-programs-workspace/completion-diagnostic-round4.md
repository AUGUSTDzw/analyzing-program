# 完成率诊断 · 第四轮：run-log 是不是压垮它的那件事

判据在派发前写死。阈值来自 `completion-diagnostic-plan.md` §6 的既定规则，
本轮**不改动任何阈值**，只把它应用到一组新条件上。

## 1. 要回答的问题

第三轮（C1 vs C3，全 3/3）没能确认「增量追加写可修」，原因是两臂都满员、没有对照。
把全部观测按「prompt 是否额外要求写 run-log」分开，出现一个未解释的模式：

| prompt 类型 | 尝试 | 静默 |
|---|---|---|
| 额外要求写 run-log（探针两轮） | 4 | **2** |
| 不要求 run-log（第三轮 6 次） | 6 | **0** |

两次静默全部落在要求 run-log 的场合。这个模式要么说明**探针的额外交付物**
是在 1597 行源码上压垮模型的那件事，要么只是运气。本轮只区分这两者。

## 2. 设计：只改一个变量

| 项 | 取值 |
|---|---|
| skill 版本 | 1.0.3 = `fac4d5a3`，与第三轮完全相同，安装位未动 |
| 源码 | `zcl_abapgit_objects_program`（1597 行，sha `bf5661698e3d`），与第三轮相同 |
| 写入方式 | **单次写**（第三轮 C1 的方式，不要求分段追加） |
| **唯一改动** | prompt 里**加回**探针那一段 run-log 要求 |
| 条件名 | R1 ×3 |
| 派发 | 3 次同时发出（与第三轮 C1 的并发度相同） |
| 回报指令 | 保持第三轮 C1 的原文不动 |

C1 与 R1 的 prompt 差异**只有** run-log 那一段：R1 = C1 + 要求写
`<name>.run-log.md`（逐条记录执行过的每条 shell 命令原文与退出码）。
回报措辞、文件名、其余全部逐字相同。

## 3. 判定（事先定死）

| R1 结果 | 结论 |
|---|---|
| ≥1 次静默 | **探针假设得到支持**：在同样输入下，加上 run-log 交付物就会出现静默。完成率里有一部分是测量装置的性质 |
| 3/3 产出 | **M3 随机假设得不到反驳**：run-log 单独不足以压垮它，此前两次静默更可能是随机。完成率问题回到「偶发」这个描述 |

两种结果都**只是方向**，n=3 每格，没有功效可言。两种结果都**不允许**书写：
任何准确率、召回或版本优劣的断言；任何"完成率是 X%"的断言。

## 4. 明确不做的

- 不用它更新 `conformance-probe-1.0.3-results.md` 里的首次完成率（n=2，协议不同，并列会造成假精确）。
- 不用它确认或否定「增量追加写」——那是第三轮的事，本轮条件里没有写入方式这个变量。
- 不重测 C3。第三轮已经证明 C3 也是 3/3，没有可分辨的空间。
- 不在派发前看结果改判定。
