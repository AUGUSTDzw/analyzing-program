# 符合性探针：1.0.2 新增的三条指令，模型照不照做

**登记时间 2026-10-07。派发之前写死。任何一份报告存在之前不得修改本文件的判据。**

## 1. 为什么测这个

1.0.1（`006719f8`）给 SKILL.md 加了「闸门输出：退出码是唯一的机器判据」一节、
第 1 步的"粘贴源码先落盘"、以及把形状闸门拆成带源码的第 7 步。这些改动的
**每一句都对着 `report_qc.py` 的控制流逐条核过**，核的是"闸门真会这么反应"。

没有核过的是另一半：**模型会不会照做**。最可能的失败有三种——
压根不传 `.abap` 源码路径、只看 `PASS` 那一行而不看退出码、遇���退出码 `2`
却当成"查过了"。这三种都不会让任何测试变红，因为它们发生在模型侧而不是代码侧。

所以这一轮测的是**可执行性**，不是效果。

## 2. 与既有阻塞的关系

`analyzing-programs-hardened/preregistration.md` 的 Blocker B 是"没有不是评委的
runner"。那条阻塞针对的是**效果测量**（判缺陷召回需要独立评委，自己生成自己判
等于自证）。本探针**不判质量**，只记录 agent 执行了什么命令、拿到什么退出码、
产出什么文件 —— 没有可自评的分数，因此不受那条阻塞约束。

**它也正因如此什么都证明不了**：见 §6。

## 4. 五项判据（派发前定死）

| # | 判据 | 怎么算达成 |
|---|---|---|
| 1 | **源码参数以 `.abap` 结尾且路径真实存在** | 运行日志里有形状闸门命令行，第二个参数以 `.abap` 结尾 |
| 2 | **形状闸门在报告写完之后运行** | 日志中闸门命令出现在"报告文件写入"之后 |
| 3 | **退出码被读作判据** | 日志或结果里引用了具体退出码数值，而不是只说"PASS" |
| 4 | **`--fidelity-only` 跑过一次** | 日志里有该子命令，且在写完之后 |
| 5 | **报告没有停在第三节中途** | 全部子程序都展开，或在报告里明写了覆盖范围 |

**判定规则（同样事先定死）**

- 每项达成 = 1 分，共 5 分。**≥4 分且第 1、2、4 项必须全达成** = 指令可执行。
- 未达 4 分，或 1/2/4 任一项缺失 = **不可执行**，此时 §7 的第二批不做。
- 该文件**没有产出任何文件** = 该项 0 分，并按项目既有规则**算一次尝试**
  （静默无输出算尝试；只有工具级中断才重派且不计）。

## 6. 这批数据能回答什么、不能回答什么

**能回答**：1.0.1 新增的指令在真实规模上**可被执行 / 不可被执行**。

**不能回答**，且不得据此书写：

- 任何准确率、召回、缺陷发现率的断言（本次不判质量，没有分数可比）
- 与任何其他版本的优劣（单臂，无对照）
- "新指令是否让报告更好"（要回答它需要的是效果测量，不是本探针）

n=2，每格单次尝试。**即使全部达成，也只能说"没观察到不遵循"**，
不能说"遵循率 100%"。
