# 更正：两轮符合性探针里的「首次完成率 1/2」受测量装置污染

**记录时间 2026-10-07。由 `completion-diagnostic-round4-results.md` 引出。**

## 1. 被更正的是什么

| 文件 | 原句 | 状态 |
|---|---|---|
| `conformance-probe-1.0.2-results.md` §5.1 | 「首次完成率 1/2（n=2），与 iteration-9b 的 41.7% 同量级」 | **撤回** |
| `conformance-probe-1.0.3-results.md` §5 | 「首次完成率两轮都是 1/2」 | **撤回** |

**撤回理由**：这两个数字来自**额外要求写 run-log** 的 prompt。第四轮在同一份源码
（`objects_program`，1597 行）、同一个 skill 版本、同样并发度下测得：
要求 run-log 时 2/3 静默，不要求时 6/6 全部产出（第三轮 C1/C3 六次）。

方向一致但**统计上不显著**（Fisher 精确检验双侧 p=0.196，仅 1.0.3 数据；
合并全部轮次双侧 p=0.085），所以正确表述是：
**探针观察到的静默可能来自测量装置本身，方向成立、样本不足。**

## 2. 不受影响的结论

两轮探针的**五项判据与判定不受影响**。判据 1、2、3、4、5 全部取自
**产出报告里的闸门命令与退出码**，而不取自 run-log 的存在：

- 判据 1：闸门命令行里的路径与后缀
- 判据 2：闸门在报告写完之后运行
- 判据 3：拿到非零退出码之后做了什么
- 判据 4：`--fidelity-only` 跑过
- 判据 5：报告有没有停在第三节中途

只有「首次完成率」这一个**附带观察**来自"有没有落盘"，而落盘这件事本身
被 run-log 交付物影响。因此撤回的只有它。

## 3. 一并记录：新记录的失败形态

「静默」这个叫法此前掩盖了三种形态，现在分开记：

| 形态 | 说明 |
|---|---|
| 完全为空 | 返回空字符串，磁盘无文件 |
| **残句 + 无文件** | 返回一句"…Writing the report."之类的话，磁盘无文件。**比静默更危险，因为它看起来像在推进** |
| 完整 | 正常产出 |

## 4. 方法论教训（本项目自己的第 N 次）

要求 agent 额外交付一份"命令与退出码记录"，看起来是纯观察手段，实际上**改变了任务**：
在 1597 行源码上它可能才是压垮模型的那件事。

这与本项目记录过的其他几次同源：
`b8f84e8` 从未被安装导致整轮拿一个版本跟自己比；
三份预注册计划随删除事故丢失；
`heading_anchor` 声称逐字一致而闸门只做子串存在性。

共同形状是：**测量装置本身进入了被测系统。**
